IDBD · Sutton, 1992

A learner that works out what to listen to.

IDBD is a rule for learning from a stream of data. It keeps a separate learning speed for every input and tunes those speeds as it goes, so it reacts fast to what matters and ignores the noise.

What IDBD does

Guess, check, correct. Then decide how hard to correct.

A thermostat wants to predict how the room temperature will change. Every minute it reads its sensors, makes a guess, sees what really happened and corrects itself. Most learning programs work this way. IDBD adds one thing: for every sensor it keeps its own learning speed, and it adjusts those speeds too.

  1. 1

    Guess

    Multiply each sensor's reading by how much it trusts that sensor, and add them up.

  2. 2

    Check

    See the real temperature change. The difference is the miss.

  3. 3

    Correct

    Change each trust a little to shrink the miss. How much depends on that sensor's speed.

  4. 4

    Tune the speeds

    If a sensor's corrections keep pushing the same way, speed it up. If they keep cancelling out, slow it down. This step is IDBD.

01 · Too many signals

Half of what this house measures is noise.

The thermostat reads six sensors. The sun on the window, the oven and the front door move the room temperature. The Wi-Fi signal, the doorbell battery and the clock do not.

Nobody tells the learner which is which. It has to work that out from the readings alone.

    02 · One speed is a bad compromise

    A single learning speed is either late or nervous.

    A plain learner corrects every sensor at one fixed speed. Set it low and it takes ages to notice the oven is on. Set it high and every flicker of the Wi-Fi signal shakes the guess.

    What we want: fast for the oven, still for the clock. No single speed does both.

    04 · A speed for every sensor

    After a while, IDBD listens to three sensors and tunes out three.

    Nobody told it which sensors matter. The speeds for the sun, the oven and the front door grew because their corrections kept agreeing. The others shrank because theirs kept cancelling out.

    Richard Sutton called the rule Incremental Delta-Bar-Delta in 1992.

    05 · The house never sits still

    What matters keeps changing. Nobody announces it.

    Clouds cross the sun. Someone opens the kitchen door. The front door swings open and shut. After each change the guesses go wrong in the same direction for a while, so IDBD keeps those three sensors fast and catches up quickly.

    06 · Play

    Play against it.

    1. You guess too. Every reading, your guess is each sensor's value times your slider, added up.
    2. A slider says what a sensor does. +1.0 means "when this sensor goes up by 1, the room warms by 1 °C". 0 means "ignore it". Below 0 means it cools the room.
    3. Closest wins. Each score is how far off that player's guesses are, typically, over the last 300 readings. Random noise keeps even a perfect player about 0.50 °C off.

    What IDBD has worked out: what each sensor does, and how fast it is still learning about it

    A sensor can barely matter right now and still be learned about fast. IDBD keeps a high speed for sensors whose effect keeps changing, so it can follow the next change.

    IDBD and the fixed-speed learner run in the idbd crate, compiled to WebAssembly, and have already seen 5,000 readings of this house. They use the settings scenario E06 selected for each house. Your score uses the same readings.
